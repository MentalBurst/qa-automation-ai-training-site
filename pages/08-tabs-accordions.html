Tabs & Accordions

Keyboard-accessible tabbed interfaces and exclusive/multi-open accordion panels, with full ARIA support.

A. Tabbed Interface

Playwright

Microsoft's end-to-end testing framework. Supports Chromium, Firefox, and WebKit. Available in TypeScript, Python, Java, and C#.

  • Auto-wait built-in
  • Network interception
  • Parallel execution
Documentation ↗

Selenium WebDriver

The pioneer of web automation. Language-agnostic, supports all major browsers via WebDriver protocol.

  • Multi-language support
  • Selenium Grid for parallel
  • Large community

Cypress

Developer-friendly E2E and component testing. Runs directly in the browser with time travel debugging.

  • Time-travel debugging
  • Real-time reloading
  • Excellent DX

Robot Framework

Keyword-driven acceptance testing framework. Highly readable, great for BDD and ATDD.

  • Keyword-driven
  • Rich library ecosystem
  • Non technical friendly

B. Exclusive Accordion (one open at a time)

Test-Driven Development (TDD) is a software development process where you write tests before writing the actual code. The cycle is: Red → Green → Refactor.
BDD extends TDD using natural language descriptions (Gherkin: Given/When/Then) to describe behaviour. It improves communication between developers, testers, and stakeholders.
The Test Pyramid describes the ideal ratio of tests: many unit tests at the base, fewer integration tests in the middle, and a small number of E2E tests at the top.
A flaky test is one that produces inconsistent results (passes and fails) without any code changes. Common causes: timing issues, network latency, dynamic IDs, race conditions.

🔵 Test Objective

  • Click tab → assert correct panel is visible
  • Arrow key → cycles tabs
  • Accordion: one closes when another opens
  • Assert aria-expanded attribute

🔵 Key Selectors

getByTestId('tab-playwright')
getByTestId('tabpanel-playwright')
// Playwright: hidden panels have [hidden]
// Assert: not toBeVisible()

getByTestId('accordion-header-1')
getByTestId('accordion-body-1')
// After click: check aria-expanded="true"

🟣 Atomic Reproduction Steps

🟢 Scenario A Tab Navigation

  1. Assert tab-playwright has class "active" and aria-selected="true"
  2. Assert tabpanel-playwright is visible
  3. Assert tabpanel-selenium is hidden
  4. Click tab-selenium
  5. Assert tab-selenium has aria-selected="true"
  6. Assert tabpanel-selenium is now visible
  7. Assert tabpanel-playwright is now hidden

🟢 Scenario B Exclusive Accordion

  1. Assert all accordions are collapsed (no "open" class)
  2. Click accordion-header-1
  3. Assert accordion-item-1 has class "open"
  4. Assert accordion-header-1 has aria-expanded="true"
  5. Click accordion-header-2
  6. Assert accordion-item-2 has class "open"
  7. Assert accordion-item-1 does NOT have class "open"

🟡 Pitfalls

  • Tab panels use the HTML hidden attribute use toBeHidden() not CSS check.
  • Accordion body height is CSS-animated assert text visibility not height transition.
  • Arrow key navigation only works when tab button has focus use focus() first.
