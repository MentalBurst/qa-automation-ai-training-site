🟣 Atomic Reproduction Steps

🟢 Scenario A Successful Login

  1. Navigate to pages/01-simple-login.html
  2. Assert page title is "Simple Login Form"
  3. Assert the login form is visible (data-testid="login-form")
  4. Type admin into the username field
  5. Type admin123 into the password field
  6. Click the Sign In button
  7. Assert #login-card is hidden
  8. Assert #login-success is visible
  9. Assert #success-username contains text "admin"

🔴 Scenario B Empty Form Submission

  1. Navigate to pages/01-simple-login.html
  2. Leave username and password fields empty
  3. Click the Sign In button
  4. Assert #username-error is visible and contains "required"
  5. Assert #password-error is visible and contains "required"
  6. Assert the form is still visible (no navigation)

🔴 Scenario C Wrong Credentials

  1. Type admin in username
  2. Type wrongpassword in password
  3. Click Sign In
  4. Assert #login-alert is visible
  5. Assert alert text contains "Invalid credentials"

🔵 Scenario D Password Toggle

  1. Type any text into #password
  2. Assert type attribute of password input is "password"
  3. Click #toggle-password
  4. Assert type attribute of password input is now "text"
  5. Click #toggle-password again
  6. Assert type is back to "password"

🟡 Pitfalls & Edge Cases

  • Do NOT assert success by URL change this is a SPA-style swap with no navigation.
  • The alert is hidden via display:none use toBeVisible() not toBeInViewport().
  • Password field type attribute changes dynamically query fresh each time.
  • Cancel button clears the form but does NOT submit assert empty fields after click.
