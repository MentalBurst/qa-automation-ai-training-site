Race Conditions & Flakiness Simulation

Intentionally tricky timing scenarios: elements that appear/disappear, content that changes, and stale references.

A. Disappearing Button

The button appears for only 2 seconds after clicking "Start". Your test must click it before it disappears.

B. Randomized Delay (1–5 seconds)

Each click adds a random delay before showing the result. Your test must use waitFor, not fixed sleep.

🟣 Atomic Reproduction Steps

🟢 Scenario A Catch the Fleeting Button

  1. Click btn-start-disappear
  2. Wait for btn-fleeting to be visible (use waitFor with timeout 3000)
  3. Click btn-fleeting before the 2-second window closes
  4. Assert disappear-result contains "success"

🟢 Scenario D Dynamic ID Anti-Pattern

  1. Locate elements by data-testid="dynamic-item-A" (stable)
  2. Click btn-regenerate-ids
  3. Assert elements still findable by data-testid
  4. Note: id attribute changed prove IDs are unreliable

🟡 Key Concepts

  • Stale reference: element cached before DOM rebuild always re-query.
  • CSS-hidden vs display:none: opacity:0 element IS in layout; display:none is NOT.
  • Random delays: never use page.waitForTimeout() always wait for the actual element.
